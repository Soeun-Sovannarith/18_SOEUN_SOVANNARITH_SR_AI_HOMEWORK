# Local Document RAG: Naive Retrieval System

A local Retrieval-Augmented Generation (RAG) assistant designed for school policy, handbook, and campus information documents. The system reads documents (`.pdf`, `.md`, `.txt`), chunks them with semantic paragraph boundaries and overlap, indexes them into persistent ChromaDB, and generates grounded, streaming answers using a local Ollama Large Language Model.

---

## Features

- **Multi-Format Ingestion**: Ingests `.pdf`, `.md`, and `.txt` files with automated text normalization and metadata extraction.
- **Paragraph-Aware Chunking**: Preserves natural paragraph boundaries; breaks long passages using sliding character overlaps to maintain context across chunk boundaries.
- **Persistent Vector Store**: Uses ChromaDB with Cosine Distance embeddings generated by `nomic-embed-text`.
- **Top-3 Vector Retrieval**: Retrieves the most relevant document chunks based on cosine similarity.
- **Real-Time Token Streaming**: Real-time token delivery in the terminal via `llama3.2`.
- **Hallucination & Fallback Protection**: Strict system prompting and distance thresholding that decline to answer when context is insufficient, automatically suppressing irrelevant reference citations.

## Chunking Strategy & Rationale

- **Strategy**: Paragraph-aware character chunking with sliding character overlap.
- **Implementation**:
  1. The document is first split on double newline boundaries (`\n\n`) to preserve cohesive, complete paragraphs.
  2. For paragraphs longer than 800 characters, it wraps and splits at natural word boundaries using a **chunk size of 800 characters** and a **sliding overlap of 120 characters**.
- **Rationale**: School regulations, policies, and course descriptions are organized into natural thematic paragraphs. Keeping paragraphs intact avoids breaking a rule mid-sentence. When paragraphs are long, a 120-character overlap ensures that critical context (like prerequisites or exceptions) isn't lost if an important statement crosses a chunk boundary.

---

## Embedding Model & Vector Database

- **Embedding Model**: Ollama `nomic-embed-text` (768-dimensional dense vector embeddings).
  - Selected for its strong performance on document retrieval and low local inference latency.
- **Vector Database**: **ChromaDB** (`chromadb.PersistentClient`) with **Cosine Distance** metric (`"hnsw:space": "cosine"`).
  - Selected for local persistence on disk, fast HNSW nearest-neighbor search, and seamless metadata filtering.

## Project Structure

| File | Purpose |
| :--- | :--- |
| `ingestion.py` | Recursively scans `data/` and parses `.txt`, `.md`, and `.pdf` files into validated Pydantic models. |
| `chunking.py` | Implements paragraph-aware chunking and fixed-window chunking strategies. |
| `embeddings.py` | Generates dense vector embeddings via local Ollama `nomic-embed-text`. |
| `vector_store.py` | Persists embeddings in ChromaDB using cosine distance; includes auto-recovery for database migrations. |
| `retriever.py` | Retrieves top-$k$ relevant chunks using ChromaDB cosine distance search. |
| `generator.py` | Assembles grounded prompt context and streams token responses from `llama3.2`. |
| `pipeline.py` | Connects retrieval and generation into unified streaming and non-streaming callable pipelines. |
| `main.py` | Terminal interface with real-time streaming and reference listing. |
| `demo_vector_check.py` | Standalone verification script for vector store retrieval quality. |
| `compare_chunking.py` | Script comparing paragraph-aware and fixed-window text chunking strategies. |

## Document Dataset (`data/`)

The `data/` folder contains documents for **Greenfield International School**:
- `school_information.txt` — Core school overview, hours, admissions, contact emails, and website URL.
- `academic_calendar.md` — Term dates, semester schedules, examination periods, and holidays.
- `campus_services.md` — Reception, library borrowing policies, cafeteria, transport, and health services.
- `school_regulations.md` — Code of conduct, safety policies, personal device rules, and disciplinary appeal procedures.
- `student_life.md` — Extracurricular activities, student clubs, and athletics.
- `tuition_and_fees.md` — Grade-level tuition rates, payment schedules, sibling discounts, and withdrawal/refund policies.
- `school_handbook.pdf` — Comprehensive student and family handbook.
