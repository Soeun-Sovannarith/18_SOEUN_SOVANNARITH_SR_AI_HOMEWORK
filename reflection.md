# Reflection

This local RAG prototype worked well because each stage is decoupled with a clear responsibility: ingestion normalizes diverse file types, chunking creates cohesive passages, embeddings capture semantic meaning, Chroma stores and retrieves them, and generation produces grounded answers. The source and distance display made retrieval transparent and easy to evaluate. Real-time token streaming significantly improved perceived latency and responsiveness.

One thing that was harder than expected was the semantic vs. keyword mismatch in pure vector search. Dense embedding models excel at broad conceptual queries, but they struggled with short, entity-specific lookups like school website URLs or specific staff email addresses. Because vector search always returns the top-k nearest neighbors regardless of relevance, generic school overviews scored high enough to drown out the exact contact information blocks. Furthermore, strictly enforcing fallbacks to prevent hallucinations required precise prompt engineering and post-retrieval validation.

For an Advanced RAG improvement, implementing Hybrid Retrieval combining BM25 keyword search with dense vector search (using Reciprocal Rank Fusion) effectively resolved the exact entity lookup weakness. For future enhancements, I would integrate a Cross-Encoder Re-ranker (such as `bge-reranker`) to re-score candidate passages after initial retrieval, query rewriting with HyDE (Hypothetical Document Embeddings) for ambiguous user questions, and hierarchical heading-aware Markdown chunking to preserve full document outline context.
